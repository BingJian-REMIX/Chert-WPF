### 当前完成度判断

Core 逻辑层覆盖度约 **85%**，App UI 层明显落后。核心矛盾一句话概括：

> **不是缺算法，是缺接线。**

最有代表性的证据：`LauncherProfile` 中 `TabTheme` / `Hud` / `Prewarm` / `Backup` / `ServerPackCacheMb` / `AutoRepairResourcePacks` / `AfkWorkflows` / `ShaderTokens` 字段**全部已定义**，而 `SettingsViewModel` 对它们的引用数是 **0**。数据模型早铺好了路，就差绑定。

同理，`BackupManager`、`NbtEditor`、`DataPackConflictDetector`、`FileChangeDetector`、`AnnualReport`、`LaunchPrewarmer` 这批 Core 类实现质量都不错，但 App 层要么零引用、要么根本没有对应 View。

### 四梯队路线

1. **第一梯队** — Core 就绪、纯补 UI：备份管理器、NBT 编辑器、数据包冲突检测、文件变更检测 + Toast、年度报告、服务器资源包缓存。做完工具箱从 11 个面板补到 16 个。
2. **第二梯队** — 规格符合度整改：全局换 ToggleSwitch、工具箱改侧边栏并打通路由、侧边栏点击保持展开、设置页补 7 个开关。
3. **第三梯队** — 补齐半成品：推荐按钮绑定、服务器添加/右键、统计真实数据、性能曲线、存档四操作、AI 助手改版。
4. **第四梯队** — 大工程新开发：皮肤编辑器像素引擎、开发工具三件套、HUD 叠加窗口、挂机工作流编辑器、真实连接服务器。

### 这份备份怎么用

- **在线看**：切到「源码浏览」标签，左侧文件树点开即读，带 C# / XAML 语法高亮。搜索框直接输入过滤文件名；输入 `>` 开头（如 `>BackupManager`）做**全文检索**，点结果行可跳转到对应位置。
- **还原**：点右上角「下载源码 ZIP」，解出来就是完整仓库结构，`dotnet build` 可直接用。
- **离线**：整份源码已内嵌在这个 HTML 里，断网照常浏览，不依赖任何 CDN 或外部资源。
- **留档**：右上角「保存此页面」可再存一份副本。

> 浏览功能依赖浏览器原生 `DecompressionStream` API（Chrome / Edge 103+、Firefox 113+、Safari 16.4+）。若浏览器过旧，页面会提示，此时直接下载 ZIP 即可，不影响备份完整性。
