# 情人节专项 · 局域网远控联动：方案与成本评估

> 对应清单 #35 ~ #40（[待定]）。按 #36 要求先出方案与成本估算，评估后再决定是否纳入 v2.6.0。
> 本文只做方案与估算，**尚未实现**，也未改动任何既有代码。

## 1. 需求原文与目标

情人节专项希望做到：

1. 自动搜索局域网内在线计算机；
2. 弹窗请求用户授权，由用户选择目标计算机（**必须显式同意，不可静默执行**）；
3. 选定后向目标机自动安装 / 部署启动器；
4. 本机与对方联动进入同一个 Minecraft 世界（局域网联机）。

目标用户场景：两台电脑在同一 Wi-Fi 下，一方点几下就能把对方「拉进」自己的世界。

## 2. 关键技术约束（决定成本的核心）

| 约束 | 影响 |
| --- | --- |
| Windows 防火墙默认阻止入站 UDP/TCP | 发现服务首次监听会触发防火墙弹窗；静默放行需管理员权限建入站规则 |
| 无凭据无法向远端写文件 / 装程序 | 「自动安装启动器」在拿到对方账号密码前不可行；SMB 管理共享需管理员且常被禁用 |
| UAC / 权限提升 | 静默安装必然触碰 UAC，属高危且易被杀软拦截 |
| 局域网不可信 | 发现 / 控制协议必须带配对码或一次性 token，否则等于开了远控后门 |
| 跨平台 | Linux 端（Chert-Linux）需再实现一遍发现服务与 Agent，工作量翻倍 |

**结论性判断：** 第 3 项「自动安装 / 部署」是整个需求里唯一**技术上不可靠**的一环，也是合规风险最高的一环。其余三项都能做。

## 3. 推荐方案（分层）

### 层一：局域网发现（必需，风险低）

- 启动器内置一个轻量发现服务，监听 UDP `47624`（可配置）。
- 探测：向 `255.255.255.255` 与 `192.168.x.255` 广播 `CHERT-DISCOVER-1` + 本机 nonce，500ms 内收集回包。
- 回包内容（JSON，只暴露最小信息）：设备名、启动器版本、是否已装 Minecraft、支持的 MC 版本列表、联动开关状态。
- 回退：广播被禁时可手动输入 IP 直连。
- 防火墙：首次监听引导用户点一次「允许访问」，并在设置页提供「重新申请防火墙例外」。

### 层二：授权弹窗（必需，风险低）

- 发现结果列表（设备名 / IP / 版本），单选。
- 二次确认弹窗明确写明：将要向该计算机发送「加入本机局域网世界」的指令，需对方屏幕上确认（双端确认）。
- 配对：本端生成 6 位一次性配对码，对方输入后才建立会话；配对码 10 分钟失效。

### 层三：联动进入同一世界（必需，风险中）

- 本端：检测本机 Minecraft 是否已 `Open to LAN`（读日志 `Local game hosted on port 25565`），或提供「一键开放局域网」按钮（向游戏窗口投递 `/publish` 指令——复用已有的 `GameKeySender`）。
- 把 `host:port` 通过已建立的会话发给对方 Agent。
- 对方 Agent：拉起 Minecraft 直连该地址（`-quickPlayMultiplayer` 或启动后投递直连指令）。

### 层四：自动部署启动器（**建议本期不做**）

- 不可靠点：无凭据写远端、UAC、杀软、防火墙。
- 降级替代：目标机需**已安装**燧石启动器（或运行随身的 `chert-agent.exe`），并在设置里打开「允许局域网联动」。首次使用给出「把启动器发给对方」的引导（复制下载链接 / 局域网共享目录路径），由对方自行安装一次。

## 4. 成本估算（人日，单人开发，含自测）

| 模块 | 工作量 | 说明 |
| --- | --- | --- |
| 发现服务（UDP 广播 + 回包协议 + 配置） | 1.5 d | Core 层协议 + App 层服务 |
| 发现结果 UI + 授权弹窗 + 配对码 | 1.0 d | 复用 Toast / 现有对话框样式 |
| 会话协议 + 一次性 token + 白名单持久化 | 1.0 d | 安全相关，不可省 |
| Agent（本地拉起游戏 / 直连 / 状态回报） | 2.0 d | 含进程通信 |
| 本端 Open to LAN 检测 + 端口解析 + 一键发布 | 1.5 d | 依赖日志解析，容错较多 |
| 防火墙引导 + 设置页开关 | 0.5 d | 文案 + 状态检测 |
| 双机联调 + 异常场景（多网卡 / 防火墙拒绝 / 对方离线） | 1.5 d | 至少两轮 |
| 文档（使用说明 + 安全说明） | 0.5 d | |
| **小计（不含自动部署）** | **≈ 9.5 d** | |
| 自动部署（远程安装） | +3.0 d | 且**成功率不可保证** |
| Linux 端对齐 | +5.0 d | 发现服务 + Agent 重写一遍 |
| **合计（全量含部署 + 双端）** | **≈ 17.5 d** | |

## 5. 风险登记

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 防火墙拦截导致「搜不到人」 | 高 | 手动输入 IP 回退 + 明确引导文案 |
| 静默安装被判定为恶意行为 | 高 | 本期直接不做，改为「对方已安装」前提 |
| 局域网内未授权控制 | 高 | 配对码 + 双端确认 + 会话超时 |
| 杀软拦截 UDP 监听 | 中 | 端口可配置、提供关闭联动的开关 |
| 日志解析拿到错误端口 | 中 | 多模式匹配 + 手动填写端口兜底 |
| 多网卡 / VPN 导致广播不走预期网段 | 中 | 遍历本机所有 IPv4 子网广播 |

## 6. 建议结论

- **本期（v2.6.0）不纳入**完整实现：全量约 17.5 人日，且核心的「自动部署」存在不可靠 + 合规双重风险，与 #36「评估后再决定」的前置要求相符。
- 若希望情人节有东西可交付，建议做 **MVP 版「一键分享局域网世界」**：
  - 本端一键 `Open to LAN`，解析出 `host:port`，生成分享文本 / 二维码；
  - 对方在启动器里粘贴地址即可直连。
  - 工作量 **≈ 2 人日**，无防火墙入站要求、无远控风险，能覆盖「一起进同一个世界」的核心诉求。
- 完整方案（含发现 + 授权 + Agent 联动，不含部署）可作为 v2.7 候选，预算 **9.5 人日**；跨平台再追加。
